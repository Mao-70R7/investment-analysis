# 项目协作规范

## 目录职责默认规则

本文档所在目录是开发工程根目录，主要保存脚本、程序、配置、规则文档和可追溯过程产物。

正式结果目录由运行布局的 `reportRoot` 指定。页面包、静态 HTML、报表、图表数据、部署清单和用户最终访问的系统文件，默认都必须输出到该目录，目录结构保持 `basic_data/...`、`deployment_manifest.json` 等当前页面系统格式。

开发目录下的 `basic_data` 仅作为页面模板、静态资源源码和历史资产来源；除显式调试或脚本中间产物外，不作为正式交付结果目录。完成开发后必须确保正式结果目录已同步更新并可独立访问。

本项目每次修改采集、加工、数据结构、字段口径、实体识别、页面包或报表展示后，必须执行数据稽核。

任务必须按“识别规则 -> 按规则执行 -> 按规则检查 -> 解释问题 -> 沉淀规则”的闭环处理。详细规范见 `文档/项目规范/任务迭代持续进化工作模式.md`。

默认执行：

```powershell
python -X utf8 节点脚本\_共享组件\生产程序\运行项目数据稽核hook.py --mode manual
```

若只检查已生成数据包，可执行：

```powershell
python -X utf8 节点脚本\_共享组件\生产程序\运行项目数据稽核hook.py --mode manual --audit-only
```

在终端中文路径编码异常时，使用等价 ASCII 包装入口：

```powershell
python -X utf8 节点脚本\_共享组件\生产程序\run_project_data_audit_hook.py --mode manual
```

发现不符合规范的字段或数据时，最终答复必须说明：

- 问题字段或数据范围。
- 根因或原因说明。
- 对页面和业务判断的影响。
- 优化建议或已修复脚本。
- 最新稽核报告路径。

发现新的问题类型时，必须持续更新：

- `config/数据稽核规则规范.json`
- `config/系统字段检查规则.json`
- `节点脚本/_共享组件/生产程序/标准化数据稽核.py`
- 必要时更新 `文档/项目规范/数据稽核Hook规范.md`
- 必要时更新 `文档/项目规范/任务迭代持续进化工作模式.md`

不得为了通过检查而删除、绕过或弱化规则；确认为误报时，必须把规则改得更精确。

## 节点化运行规范

- 根目录正式运行入口仅为 `00_每日数据更新并发布_唯一入口.bat`；生产和运维逻辑统一位于 `节点脚本`。
- 每个叶子节点必须保留 `SKILL.md`、`node.json`、`run.ps1`、`src` 和 `tests`，并遵循 `节点脚本/00_调度框架/schemas/node.schema.json`。
- 节点必须原子生成 `node_result.json`，退出码为 0 但验证器不通过时仍视为失败。
- 主库写入节点必须使用 `main_db_write` 资源锁；设备节点必须使用 `device` 资源锁；发布节点必须使用 `publish_repo` 资源锁。
- 兼容入口只允许位于 `节点脚本/99_兼容入口`，不得被新增到每日 DAG 或根目录。
- 生产代码不得使用固定盘符、旧 `scripts` 路径或按 `Path(__file__).parents[n]` 猜测项目根目录。

如果 hook 输出 `RULE_CATALOG_MISSING`，必须补充规则库；如果输出 `PERSISTENT_AUDIT_ISSUE`，必须把持续问题升级为明确修复任务或写明短期接受的业务影响。
