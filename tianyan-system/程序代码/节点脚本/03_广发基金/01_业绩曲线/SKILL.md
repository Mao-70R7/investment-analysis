# 广发业绩曲线

节点ID：`gffunds_performance`  
执行入口：`run.ps1`  
超时：`7200` 秒  
资源锁：无。该节点使用广发公开接口，不启动或占用真机。

## 目标

以独立节点执行“广发业绩曲线”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：广发业绩曲线批次和成功失败清单。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

ttfund_incremental

## 业务口径

广发业绩曲线每日轻量刷新，以 App 对应公开接口披露为优先口径。

- 首轮并发采集全部策略。
- 仅对失败策略执行两轮低并发、递增等待重试。
- 仍失败时复用该策略最近一次成功的原始曲线，并明确记录来源和源端错误。
- 个别策略比本批最新披露少一个交易日属于允许情况，只告警，不阻断更新。
- 个别策略披露更慢或临时无返回时保留缺口，但只要可用曲线覆盖率不低于 `95%`，节点继续完成。
- 无任何可用曲线或可用覆盖率低于 `95%` 时，才阻断后续入库和发布。

## 进度单位

`只策略`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

对象级先执行两轮失败项重试；节点整体仍失败时，进程级最大尝试次数为 `2`。该节点不依赖设备，因此不执行真机重试。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `critical`。失败会阻断依赖节点以及成功备份、发布，已通过验收的上游节点保留供续跑。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node gffunds_performance --run-id <run_id>
```

仅调试本节点、不执行天天投顾等依赖节点：

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node gffunds_performance --standalone
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

接口可能在晚间分批更新，策略之间允许存在一个交易日的短暂差异；报告通过告警和缺口清单保留该信息。
