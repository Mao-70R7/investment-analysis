# 广发仓位与调仓

节点ID：`gffunds_collect`  
执行入口：`run.ps1`  
超时：`10800` 秒  
资源锁：`无`

## 目标

以独立节点执行“广发仓位与调仓”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：广发仓位、调仓批次及对象级结果。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

gffunds_performance

## 业务口径

每日同时分页扫描广发基金 App 同源的普通 `GFJJ` 策略目录和目标盈 `ZY` 期次目录，再把普通目录、新发现 ID、首页和历史普通策略 ID 合并采集。普通策略采集曲线、当前基金仓位和调仓；目标盈期次只采期次自身公开目录、基础配置和协议，策略说明书按 URL 去重下载并映射到同说明书的全部期次。匿名接口返回的母策略曲线、仓位和调仓不得归属到 `ZY` 期次；期次自身详情和仓位登录可见时仍标记为缺口。当批摘要必须记录两个目录的结束证据、目录新增、已采新增、遗漏 ID 以及历史下架期次。不在本节点重复更新底层基金净值。

## 进度单位

`只策略`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `2`。设备对象失败时在同一真机内宽松重试，剩余项进入缺口清单，不因个别对象失败中断整个批次。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `optional`。渠道失败时保留旧库，主链可继续处理其他渠道；已通过验收的上游节点保留供续跑。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node gffunds_collect --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

目标盈期次自身详情与仓位需要客户登录态；当前公开采集不保存或自动化客户凭据。历史下架期次保留在数据库中，不用仅有 ID 的空白记录覆盖。
