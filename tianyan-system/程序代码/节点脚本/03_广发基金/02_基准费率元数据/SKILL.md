# 广发基准费率元数据

节点ID：`gffunds_metadata`  
执行入口：`run.ps1`  
超时：`7200` 秒  
资源锁：`main_db_write`

## 目标

以独立节点执行“广发基准费率元数据”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：广发基准费率元数据及缺口。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

process_load

## 业务口径

广发基准和费率按缺失或 7 天过期刷新，脚本解析失败时才允许进入协议补采。

## 进度单位

`只策略`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `2`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

同一批次重复执行使用事务或批次目录覆盖，只有完整验证后才提交；输入指纹变化会使下游失效。

## 失败影响

关键级别为 `optional`。失败只记 warning，不否定已经完成的数据更新或发布。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node gffunds_metadata --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
