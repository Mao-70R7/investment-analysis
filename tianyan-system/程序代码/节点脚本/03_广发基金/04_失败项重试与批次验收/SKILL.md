# 广发失败重试与批次验收

节点ID：`gffunds_gate`  
执行入口：`run.ps1`  
超时：`600` 秒  
资源锁：`无`

## 目标

以独立节点执行“广发失败重试与批次验收”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：广发渠道验收结论和阻断缺口。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

gffunds_collect

## 业务口径

只有广发必需输出、对象计数和批次状态均通过，且普通策略目录和目标盈期次目录分页均已证明结束、两个目录全部 ID（特别是库外新增 ID）均进入当批 `strategy_master`，才允许后续入库。曲线、调仓响应和最新基金仓位覆盖率以普通 `GFJJ` 核心策略为分母；`ZY` 期次按公开元数据完整性验收，不因登录态数据缺口稀释核心覆盖率，也不得用母策略数据补齐。

## 进度单位

`项检查`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `optional`。失败只阻断广发基金当批覆盖并保留旧库，主链可继续处理其他渠道。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node gffunds_gate --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

目标盈期次自身详情与仓位要求登录；验收只确认公开元数据及血缘隔离，不宣称期次业绩、仓位或调仓完整。
