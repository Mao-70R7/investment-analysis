# 且慢目录增量与新策略采集

节点 ID：`qieman_collect`

## 目标

通过本机 DPAPI 加密保存的且慢只读 API key，逐日重扫关键词目录、获取官方当前仓位和精确基准，并通过公开签名接口增量下载净值与调仓/发车历史。目录中相对上一验收批次新增的策略必须在同一批完成历史采集。

## 安全边界

- 不使用 ADB，不申请 `device` 锁，可与天天投顾设备采集并行。
- 仅允许与本次调度 `runId` 相同的 `daily_update.lock`，其他生产锁继续阻断。
- API key 仅在本机进程内通过 DPAPI 解密，不写日志和标准化文件。
- 网络下载使用最近净值日回看 7 天、历史事件遇到已知边界即停止；标准化产物仍是可独立入库的完整当前快照。
- 信号历史默认 25 条分页、普通历史 100 条分页；单请求允许持续传输，120 秒没有新数据才判定空闲超时，单次总时限 600 秒并最多重试 4 次。节点总上限 12 小时，避免因策略数或响应体增大被过早终止，同时仍保留有界超时防止永久挂死。
- 历史采集每 50 个策略主动结束并重启一次 Node 子进程；每段原子复用同一批次检查点和已经验证的原始文件。单个子进程异常退出时最多重启 4 次，只处理尚未完成的策略，不从头下载整个目录。
- 关键词并集只声明“已执行发现范围下限”，不冒充官方总数。
- 发车指令比例不等于组合仓位，兼容投影不得进入普通官方调仓表。

## 输出

- `normalized/qieman/<entity>/<runId>/<runId>.jsonl`
- `normalized/qieman/collection_summary/<runId>/<runId>.json`
- `raw/qieman/signed_history/<runId>` 原始增量合并快照
- 节点目录内采集结果、基础字段补齐报告、专项稽核报告

## 失败处理

本节点为可选渠道节点。DPAPI 文件缺失、认证失效、目录未闭合或专项稽核出现 error 时，本批且慢不进入 gate/load，已有主库且慢数据保持不变，天天及其他渠道继续运行。

少数旧策略的调仓历史在长超时和重试后仍失败时，只有存在上一批“完整且成功”的同策略历史，才允许保留该历史并发出 `QIEMAN_HISTORY_REFRESH_RETAINED_BASELINE` warning；官方净值继续按本批数据更新，下一批会再次尝试该历史。新增策略或没有成功基线的策略不得走保留路径，必须失败阻断。

若 Node 子进程出现 Windows 快速失败或网络层异常退出，节点必须先读取同批次 `checkpoint.json`，从最后一个已验证策略继续；只有同一分段连续 4 次仍不能闭合时才判定渠道失败。不得删除检查点后全量重跑，也不得把未闭合分段发布为成功快照。

批次 gate 以全部目录策略为分母，要求至少 98% 的策略净值达到本批源端最新日或仅滞后 1 个工作日；业绩非空覆盖仍须独立达到 99%。事务提交前继续严格核对主库最新日期、最新日策略数与批次摘要闭合，避免把可接受的源端披露延迟误当成入库丢数。
