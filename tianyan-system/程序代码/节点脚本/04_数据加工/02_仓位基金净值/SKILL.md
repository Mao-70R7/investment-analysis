# 仓位基金净值

节点ID：`fund_nav`  
执行入口：`run.ps1`  
超时：`14400` 秒  
资源锁：`main_db_write`

## 目标

以独立节点执行“仓位基金净值”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：基金净值批次、基金级结果和主库最新净值日。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

process_load

## 业务口径

新基金补成立以来完整净值，已有基金按各自最新净值日补增量；明确空返回与失败分开统计。

## 进度单位

`只基金`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

同一批次重复执行使用事务或批次目录覆盖，只有完整验证后才提交；输入指纹变化会使下游失效。

## 失败影响

关键级别为 `critical`。失败会阻断依赖节点以及成功备份、发布，已通过验收的上游节点保留供续跑。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node fund_nav --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
