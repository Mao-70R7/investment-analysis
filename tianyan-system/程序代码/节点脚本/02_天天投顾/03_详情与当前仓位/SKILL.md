# 天天详情与当前仓位组件

节点ID：`ttfund_holding_component`  
执行入口：`run.ps1`  
超时：`60` 秒  
资源锁：`无`

## 目标

说明天天复合采集节点中的业务子阶段；日常由天天批次验收节点统一驱动并记录具体失败子阶段。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：子阶段说明和排障入口。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

无。

## 业务口径

记录天天复合采集器内部子阶段的责任边界，不单独执行数据写入。

当前仓位任务只有在策略详情和 App 原始当前持仓均成功时才算完成。详情成功但持仓缺失仍进入本设备第二轮和备用设备失败项补采；进度中的失败数按当前仓位缺失数统计，不以是否抛出异常代替业务完整性。

## 进度单位

`只策略`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `optional`。失败会阻断依赖节点以及成功备份、发布，已通过验收的上游节点保留供续跑。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node ttfund_holding_component --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

当前为复合采集器的子阶段说明节点，不单独进入每日DAG；排障时按天天批次摘要中的失败阶段定向调用原采集程序。
