# 天天失败重试与批次验收

节点ID：`ttfund_incremental`  
执行入口：`run.ps1`  
超时：`28800` 秒  
资源锁：`device`

## 目标

以独立节点执行“天天失败重试与批次验收”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：天天原始批次、标准化数据、缺口与渠道验收结果。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

device_select

## 业务口径

天天基础信息按缺失或 7 天过期刷新，当前仓位每日刷新，调仓只补差异，业绩补到最新披露日。

## 进度单位

`只策略`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。单策略在当前设备最多尝试两次；同一设备连续出现 5 个白屏、加载失败或设备不可用时执行软熔断，不再逐项空跑，已失败项和未处理项统一转实体手机补采。

Windows PowerShell 读取策略结果数组必须通过 `_共享组件/生产程序/json_array_helpers.ps1` 中的 `Read-JsonArrayStrict`。主采结果缺失、损坏、不是数组或策略ID重复时必须阻断本节点，不能把整批目标自动当作失败项送备用设备；软熔断产生的未处理策略必须由期望ID差集显式进入备用设备清单。备用设备结果无效时保留原失败项并写入缺口，不影响已成功主采结果。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

运行配置为渠道级 `optional`。零星、可追踪的策略缺口记为 warning，不阻断其他渠道和已成功数据；结果文件损坏、策略ID重复等结构性错误仍阻断本节点。发布前必须披露天天渠道剩余缺口，不能把旧水位策略计为本次成功更新。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node ttfund_incremental --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
