# 天天失败重试与批次验收

节点ID：`ttfund_incremental`  
执行入口：`run.ps1`  
超时：`28800` 秒  
资源锁：`device`

## 目标

以独立节点执行“天天失败重试与批次验收”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：天天原始批次、标准化数据、缺口与渠道验收结果。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

device_select

## 业务口径

天天基础信息按缺失或 7 天过期刷新，当前仓位每日刷新，调仓只补差异，业绩补到最新披露日。

## 进度单位

`只策略`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。设备对象失败时在同一真机内宽松重试，剩余项进入第二批次补采和最终缺口清单。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `optional`。失败只影响当前渠道；其他可用渠道继续执行。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node ttfund_incremental --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
