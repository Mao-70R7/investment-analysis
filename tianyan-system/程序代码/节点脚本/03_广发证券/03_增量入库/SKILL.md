# 广发证券财富管家增量入库

节点ID：`gfsec_fima_load`  
执行入口：`run.ps1`  
超时：`1800` 秒  
资源锁：`main_db_write`

## 目标

以独立节点执行“广发证券财富管家增量入库”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：主库中财富管家策略、业绩、持仓与调仓行数。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

gfsec_fima_gate

## 业务口径

只消费通过财富管家门禁的精确批次，在 main_db_write 资源锁内事务替换该渠道数据。

## 进度单位

`张表`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

同一批次重复执行使用事务或批次目录覆盖，只有完整验证后才提交；输入指纹变化会使下游失效。

## 失败影响

关键级别为 `optional`。失败只影响当前渠道；其他可用渠道继续执行。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node gfsec_fima_load --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
