# 首次初始化

节点ID：`runtime_initialize`  
执行入口：`run.ps1`  
超时：`7200` 秒  
资源锁：`无`

## 目标

以独立节点执行“首次初始化”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：初始化与工作区检查报告。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

无。

## 业务口径

建立相对路径运行布局、兼容连接并执行首次完整检查。除不可变文件哈希外，还必须依据 `迁移基线/migration_manifest.json` 检查标准化基线、设备缓存、基金穿透缓存、协议缓存、最近采集批次及 F10 基准文件；声明数量不足或文件缺失时初始化失败。

## 进度单位

`项检查`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `critical`。失败会阻断依赖节点以及成功备份、发布，已通过验收的上游节点保留供续跑。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node runtime_initialize --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。工作区检查报告中的 `baselineIntegrity` 和 `runtimeBaselineIntegrity` 均须通过。

## 已知限制

开发目录没有迁移清单时，运行基础数据检查返回 `not_applicable`；迁移运行工作区必须存在迁移清单并通过检查。
