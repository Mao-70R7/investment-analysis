# 最小发布集发布

节点ID：`publish`  
执行入口：`run.ps1`  
超时：`10800` 秒  
资源锁：`publish_repo`

## 目标

以独立节点执行“最小发布集发布”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：最小发布集、Git 提交和推送结果。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

data_audit

## 业务口径

只发布通过门禁的正式结果，提交并推送最小发布集仓库。

## 进度单位

`个文件`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `publish`。发布失败保留数据成功状态和最近成功备份，只允许从交付节点恢复。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node publish --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
