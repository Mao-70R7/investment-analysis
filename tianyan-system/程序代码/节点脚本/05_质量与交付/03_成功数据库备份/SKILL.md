# 成功数据库备份

节点ID：`database_backup`  
执行入口：`run.ps1`  
超时：`14400` 秒  
资源锁：`main_db_write`

## 目标

以独立节点执行“成功数据库备份”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：一致性数据库备份及滚动保留结果。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

data_audit

## 业务口径

仅当前置数据与稽核成功后使用 SQLite Backup API 备份，整个备份目录最多只保留最近一个已验证成功版本。

## 进度单位

`个版本`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

同一批次重复执行使用事务或批次目录覆盖，只有完整验证后才提交；输入指纹变化会使下游失效。

## 失败影响

关键级别为 `optional`。失败只记 warning，不否定已经完成的数据更新或发布。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node database_backup --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
