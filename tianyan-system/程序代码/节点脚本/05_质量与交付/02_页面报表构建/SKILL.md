# 最小发布源报表构建

节点ID：`report_build`  
执行入口：`run.ps1`  
超时：`14400` 秒  
资源锁：`无`

## 目标

以独立节点执行“页面报表构建”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：运行状态目录中的最小发布源、基础数据部署清单和页面构建校验。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

strategy_governance

## 业务口径

每日只从主库重建最小发布包需要的基础页面与报表源，不直接手改生成结果，不覆盖正式完整 `reportRoot`。

## 进度单位

`个报表步骤`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `critical`。最小发布源缺少页面、数据包或部署清单时阻断稽核和发布；暂停更新的完整报表不参与每日节点成败判断。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node report_build --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

`full_data_statistics_report`、`strategy_center`、广发独立监控页和 QD 独立专题页当前暂停每日更新；需要恢复时必须显式调整 `config/daily_update_policy.json` 并重新验收。
