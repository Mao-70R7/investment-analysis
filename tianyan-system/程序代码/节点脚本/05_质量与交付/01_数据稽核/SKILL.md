# 项目完整数据稽核

节点ID：`data_audit`  
执行入口：`run.ps1`  
超时：`14400` 秒  
资源锁：`无`

## 目标

以独立节点执行“项目完整数据稽核”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：数据稽核报告、规则问题和业务缺口。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

report_build

## 业务口径

按规则库稽核刚生成的最小发布源；数据 error 阻断，业务 warning 保留并继续。每日运行不重复执行全工程静态扫描，代码修改后的项目 hook 仍必须执行完整静态检查。

## 进度单位

`项规则`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点失败后由调度器按清单重试；不允许把输出校验失败当作成功。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `critical`。核心数据或页面包完整性 error 会阻断备份和发布；可披露覆盖率 warning 不阻断。稽核通过后只传递临时最小发布源，不提升或覆盖正式完整报表目录。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node data_audit --run-id <run_id>
```

如需在不触发每日 DAG、不写主库的情况下执行跨域深度检查：

```powershell
python -X utf8 程序代码\节点脚本\_共享组件\生产程序\run_deep_data_audit.py
```

深检会在检测到存活的 `daily_update.lock` 或 `main_db_write.lock` 时默认停止，结果规范见 `文档/项目规范/深度数据检查规范.md`。

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
