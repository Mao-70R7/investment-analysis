# 天眼系统迁移运行说明

## 目录用途

- `程序代码`：每日更新、采集、加工、稽核、页面生成和发布脚本。当前迁移包按受控快照生成，通过 Syncthing 更新。
- `数据库`：主数据库、监控库和更新状态库。
- `采集数据`：天天投顾、广发基金 App 的最近完整标准化基线和不可重建缓存。
- `结果文件/全市场投顾分析平台`：正式页面输出。
- `结果文件/最小发布集`：独立 Git 仓库，每日成功后推送 GitHub Pages。
- `运行状态`：日志、检查结果、临时目录和互斥锁。
- `数据库备份`：整个目录最多只保留最近一个已验证成功版本。
- `迁移基线`：迁移清单、数据库水位、文件哈希和最新稽核摘要。
- `运行环境`：新服务器本机创建的 Python 3.12 虚拟环境，不从旧机器复制。

## 新服务器首次使用

1. 等待 Syncthing 显示本目录“同步完成”，确认旧电脑没有运行每日任务。
2. 在配置的实体手机上安装并登录天天基金 App，完成登录认证、USB 调试和 ADB 授权。
3. 双击 `首次初始化与检查.bat`。缺少运行环境时会自动检查并按需通过 winget 安装 Python 3.12、Git、Node.js，再创建工作区 Python 环境和安装依赖；也可以单独运行 `安装或检查运行环境.bat` 进行修复。
4. 如需实体手机兜底，在实体手机开启 USB 调试并确认授权；把 ADB 序列号填入 `本机配置/runtime.local.json` 的 `physicalDeviceId`。
5. 配置 GitHub 提交身份和推送凭据：先执行 `git config --global user.name "你的 GitHub 用户名"`、`git config --global user.email "你的 GitHub 邮箱或 noreply 邮箱"`；再在 `结果文件/最小发布集` 打开终端执行 `git push --dry-run origin main`，按 Git Credential Manager 提示登录。
6. 初始化会校验文件哈希、SQLite 完整性、磁盘、依赖、设备、GitHub 推送和 Pages 访问，并建立初始成功备份。
7. 直接双击 `00_每日数据更新并发布_唯一入口.bat` 完成全流程，不需要输入任何参数；检查控制台退出码为 0、最新日志、数据库水位、GitHub 提交和 Pages 版本。

## 日常规则

- 外部调度工具只需直接调用 `00_每日数据更新并发布_唯一入口.bat`，不传参数。
- 外部调度使用已登录的固定 Windows 账户；实体手机必须保持在线、解锁、ADB 已授权且 App 登录有效。
- 每次仅使用配置的实体手机；首轮失败项由同一真机执行第二批次补采，剩余缺口进入最终清单。
- 已有实例运行时不会启动第二个实例。旧电脑和新服务器不得同时运行更新。
- 成功批次才进入主库、正式页面、滚动备份和 GitHub 发布；失败批次保留日志但不标记为成功版本。

## Syncthing 使用限制

- 首次迁移可以完整同步整个目录，但同步完成前不要启动每日任务。
- 正式切换后只允许新服务器写数据库和运行结果，旧电脑停止每日任务。
- 不要在每日任务运行期间从另一台电脑覆盖 `数据库`、`采集数据`、`运行状态`、`结果文件` 或 `数据库备份`。
- 后续程序更新可在每日任务停止时同步 `程序代码`，同步完成后先运行 `检查迁移工作区.bat`，再恢复外部调度。
- Python 虚拟环境属于机器本地文件；若 Syncthing 同步规则允许，建议忽略 `运行环境/`，并在每台机器分别运行环境安装脚本。

## 常用入口

- `安装或检查运行环境.bat`：安装或修复运行依赖；只检查时传入 `-CheckOnly`。
- `首次初始化与检查.bat`：首次完整验收并创建基线备份。
- `检查迁移工作区.bat`：复查环境、数据库、设备、GitHub 和 Pages。
- `00_每日数据更新并发布_唯一入口.bat`：唯一每日生产入口。

## 故障定位

- 控制台完整日志：`运行状态/logs/daily_update_console`。
- 每日阶段摘要：`运行状态/logs/daily_update`。
- 工作区和环境检查：`运行状态/outputs/workspace_check`。
- 设备预检：`运行状态/outputs/device_preflight`。
- 数据稽核：`运行状态/outputs/data_audit` 和 `运行状态/outputs/data_audit_hook`。
- 迁移时数据库基线：`迁移基线/migration_manifest.json`。
