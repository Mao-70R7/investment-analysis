# 真机选择与预检

节点ID：`device_select`  
执行入口：`run.ps1`  
超时：`900` 秒  
资源锁：`device`

## 目标

以独立节点优先验证配置的实体手机；配置连接 ID 失效时自动发现唯一可用实体手机，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：本批次真机 ID、预检结果和失败原因。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

source_readiness

## 业务口径

每次运行优先选择 `runtime.local.json` 中配置的实体手机；配置连接 ID 失效时，从 ADB 在线设备中自动选择唯一通过 App、缓存、登录态和非模拟器校验的实体手机。模拟器和本机回环 ADB 设备不得进入生产更新。本批次的详情、当前持仓、调仓历史、官方曲线设备复核和失败项补采全部固定使用该真机。设备选择阶段只做只读健康检查，不主动拉起 App。

## 进度单位

`台设备`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。节点内部对真机预检最多尝试 `3` 次；进入采集后单策略内部最多尝试 `2` 次，失败策略再由同一真机执行第二批次补采。个别策略失败只进入缺口清单，不中断其他策略。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

节点失败影响为 `warning`。依赖真机的 App 采集节点不能启动，但其他独立节点仍按调度规则继续；已通过验收的上游节点保留供续跑。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node device_select --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

实体手机需要保持 ADB 授权、解锁、在线并已登录天天基金 App。三次预检后仍不可用时，不得改用模拟器；应记录设备缺口并等待真机恢复后续跑。
