# 真机选择与预检

节点ID：`device_select`  
执行入口：`run.ps1`  
超时：`900` 秒  
资源锁：`device`

## 目标

以独立节点执行“真机选择与预检”，形成可重试、可验证、可追溯的故障边界。

## 输入

- 工作区根目录、运行批次ID和节点运行目录。
- 上游节点通过校验的结果及统一运行环境变量。

## 输出

- 原子写入 `node_result.json`，并在尝试目录保留 `console.log` 与 `artifacts.json`。
- 节点业务输出：本批次真机 ID、选择方式、预检结果和失败原因。
- 结果必须包含状态、退出码、输入指纹、输出水位、计数、警告、错误、日志和校验结论。

## 依赖节点

source_readiness

## 业务口径

优先选择配置的实体手机；配置连接 ID 失效时自动发现唯一通过校验的非模拟器真机，且预检不主动拉起 App。

## 进度单位

`台设备`。长任务必须持续输出已完成数量、总数和当前动作。

## 重试策略

进程级最大尝试次数为 `1`。设备对象失败时在同一真机内宽松重试，剩余项进入第二批次补采和最终缺口清单。

## 幂等性

输入指纹一致、结果文件存在且验证通过时可跳过；重新执行不得制造重复业务记录。

## 失败影响

关键级别为 `optional`。失败只记 warning，不否定已经完成的数据更新或发布。

## 手工复跑

```powershell
& ".\00_每日数据更新并发布_唯一入口.bat" node device_select --run-id <run_id>
```

## 验证方法

检查节点结果中的退出码、`validation.status`、业务计数、水位和产物路径，不得只看进程退出码。

## 已知限制

无。
