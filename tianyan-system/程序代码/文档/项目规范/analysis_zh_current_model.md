# 当前可落地分析层表结构

这份结构只覆盖当前已经拿到的数据，不提前依赖以下两类未来数据：

- 底层基金日度收益时间序列
- 可回放的历史持仓时间序列

当前版的目标是先把三路现有数据稳定落成可分析的“长表结构”，便于：

1. 做横截面策略对比
2. 做当前持仓风格分类和分组对比
3. 做官方历史调仓事件与调仓明细分析
4. 为后续补齐基金日度收益和历史持仓后，直接扩展成调仓质量分析库

对应 SQL 文件：

- [analysis_zh_current.sql](/E:/AI工作区/投顾数据处理/schemas/analysis_zh_current.sql)

## 建议存储形态

建议主存储使用：

- `DuckDB`
- 明细表持久化为 `Parquet`

原因：

- 比 Excel 更适合后续 join、分组、窗口函数和事件研究
- 比单纯 SQLite 更适合大表扫描和分析型查询
- 与 Python / pandas / polars 兼容性更好

Excel 继续作为查看层，不作为主分析库。

## 当前主表

### 1. `渠道信息`

用途：渠道维表。

核心字段：

- `渠道ID`
- `渠道名称`
- `渠道类型`
- `官方站点`
- `登录要求`

### 2. `策略信息`

用途：策略主档，一条策略一行。

核心字段：

- `统一策略ID`
- `渠道ID`
- `渠道策略ID`
- `策略名称`
- `投顾机构`
- `策略类型`
- `风险等级`
- `成立日期`
- `建议持有时长`
- `起投金额`
- `投顾费率`
- `业绩基准`
- `标签JSON`

说明：

- `统一策略ID` 建议固定为 `渠道ID__渠道策略ID`
- 当前不做跨渠道“同名策略合并”

### 3. `策略日度业绩`

用途：保存当前已拿到的日度或累计业绩明细。

核心字段：

- `统一策略ID`
- `交易日期`
- `单位净值`
- `日收益率_百分比`
- `累计收益率_百分比`
- `基准收益率_百分比`
- `最大回撤_百分比`
- `业绩区段名称`
- `业绩区段类型`

说明：

- 中欧这条线最完整
- 广发当前更偏“累计收益序列”，`日收益率_百分比` 可为空
- 天天当前只有最新单日快照，历史表现主要放在 `策略区间业绩`

### 4. `策略区间业绩`

用途：保存近 1 周、近 1 月、近 1 年、成立来等区间收益。

核心字段：

- `统一策略ID`
- `统计日期`
- `区间代码`
- `区间名称`
- `策略收益率_百分比`
- `基准收益率_百分比`

说明：

- 这张表当前主要承接天天基金样例
- 不和 `策略日度业绩` 混表

### 5. `策略当前持仓分组`

用途：保存当前持仓的分组权重。

核心字段：

- `统一策略ID`
- `持仓日期`
- `披露日期`
- `分组名称`
- `分组权重_百分比`
- `基金数量`

说明：

- 这张表非常重要，尤其适合你后续做“持仓风格分类、对比”
- 天天很多策略没有精确单基金权重，但仍有分组权重，所以必须单独保留

### 6. `策略当前持仓`

用途：保存当前持仓基金明细。

核心字段：

- `统一策略ID`
- `持仓日期`
- `披露日期`
- `基金代码`
- `基金名称`
- `资产类型`
- `分组名称`
- `基金权重_百分比`
- `分组权重_百分比`
- `基金净值`
- `基金净值日期`
- `最新日涨幅_百分比`
- `是否精确权重`

说明：

- 这张表只表达“当前持仓”
- 不强行承担“可回放的历史持仓”语义
- 广发样例里要先剔除 `0%` 记录再入这张表

### 7. `策略调仓事件`

用途：保存官方历史调仓事件主表。

核心字段：

- `调仓事件ID`
- `统一策略ID`
- `调仓日期`
- `上次仓位日期`
- `本次仓位日期`
- `披露日期`

- `调仓原因`
- `上次仓位日期是否推断`

- `事件时间`

说明：

- 这张表只记录事件头，不放基金级变动

### 8. `策略调仓明细`

用途：保存官方历史调仓的基金级变动明细。

核心字段：

- `调仓明细ID`
- `调仓事件ID`
- `统一策略ID`
- `调仓日期`
- `基金代码`
- `基金名称`
- `分组名称`
- `调前权重_百分比`
- `调后权重_百分比`

说明：

- 这张表是后续调仓质量分析的核心事件底表
- 当前先保存“官方披露结果”
- 未来补齐基金日度收益后，再基于这张表向前做质量测算

### 9. `基金信息`

用途：底层基金维表。

核心字段：

- `基金类型`
- `跟踪指数`

说明：

- 这张表当前足够支持基础风格分类
- 未来可继续补更细的风格标签体系

### 10. `数据来源清单`

用途：记录每个策略当前分析层数据来自哪些标准化文件。

- `采集批次ID`
- `采集时间`

说明：

- 主要用于审计和回溯，不是分析主表

## 为什么不建“历史持仓表”

当前先不单独建“历史全量持仓表”，原因是你自己已经明确，这部分关键数据还没补齐：

- 缺少底层基金日度收益时间序列
- 缺少可回放的历史持仓时间序列

如果现在硬建一张“历史持仓表”，会混入三种不同语义：

1. 当前持仓快照
2. 调仓后完整持仓
3. 仅基金级调仓增减明细

后续分析时容易误用。

所以当前版故意拆成：

- `策略当前持仓`
- `策略调仓事件`
- `策略调仓明细`

等未来补齐后，再新增：

- `策略历史持仓快照`
- `基金日度收益`

这样扩展最稳，不会推翻现有结构。

## 当前最适合的分析起点

在现有数据下，已经适合做：

1. 策略横截面对比
2. 当前持仓大类分组对比
3. 官方调仓频率、方向、集中度分析
4. 调仓行为标签统计

还不适合严格做：

1. 调仓胜率
2. 调仓赔率
3. 调仓后收益贡献归因

因为这三类必须依赖未来要补的两张时间序列表。
