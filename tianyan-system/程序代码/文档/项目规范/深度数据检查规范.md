# 深度数据检查规范

## 目标

`run_deep_data_audit.py` 用于对投顾系统正式主库、正式页面包、最近生产运行、备份和官方渠道批次做一次跨域、只读的深度检查。它不替代每日 DAG 中的标准化数据稽核，而是把数据库关系、策略持仓、调仓、基金净值、经济暴露、页面部署和既有专项稽核汇总到一份可追溯报告。

## 安全边界

- SQLite 使用 `mode=ro` 和 `PRAGMA query_only=ON` 打开。
- 不写主库、不修改页面包、不触发采集、加工、备份或发布节点。
- 默认检测 `daily_update.lock` 和 `main_db_write.lock`；发现对应存活进程时停止检查。
- 不把推荐产品、候选基金或模拟问卷结果当成真实持仓或真实调仓。
- 渠道没有披露仓位或调仓时保留真实缺口，不推断或合成数据。

## 执行命令

在工作区根目录执行：

```powershell
python -X utf8 程序代码\节点脚本\_共享组件\生产程序\run_deep_data_audit.py
```

常用参数：

```text
--db-path PATH
--report-root PATH
--output-root PATH
--run-id ID
--sample-limit N
--skip-quick-check
--skip-standard-audit
--skip-public-fund-audit
--skip-official-channel-audit
--fail-on-error
```

只有在确认并接受与生产读并发风险时才可使用 `--allow-active-run`。日常人工深检不应使用该参数。

## 检查范围

1. SQLite `quick_check`、核心表和表结构。
2. 策略父子表孤儿记录、业务主键重复、渠道覆盖。
3. 当前持仓快照、基金数量、仓位数值、合计仓位和重复持仓。
4. 策略业绩数值与日期、最新业绩时效性。
5. 调仓事件与明细关联、变动前后仓位、单事件权重约束。
6. 基金信息、基金净值、持仓基金净值覆盖、经济暴露快照。
7. 最近一次正式日更、成功备份数量、部署清单和页面质量包。
8. 现有标准化数据稽核、公募基金有效性、官方渠道质量和页面完整性专项检查。

## 输出

默认输出目录：

```text
运行状态\outputs\deep_data_audit\<日期>\<run_id>\
```

主要产物：

- `deep_data_audit_report.json`：机器可读的完整结果、样例、指标和组件报告。
- `deep_data_audit_report.md`：业务可读的深度检查报告。
- `components\...`：各专项稽核原始报告。
- `运行状态\outputs\deep_data_audit\latest_summary.json`：最新结果索引。
- `运行状态\outputs\deep_data_audit\latest_report_path.txt`：最新 Markdown 报告路径。

## 状态口径

- `error`：存在正式规则错误、数据库关系错误、页面主库不一致或其他阻断问题。
- `warn`：数据可用但有披露缺口、时效性不足或非阻断覆盖率问题。
- `ok`：本次执行范围内未发现错误或警告。

正式放行仍以项目标准化数据稽核和发布门禁为准。深检脚本中的补充检查用于定位和解释，不得通过弱化正式规则来消除问题。
