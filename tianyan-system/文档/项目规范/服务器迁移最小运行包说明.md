# 天眼系统服务器迁移最小运行包说明

## 1. 迁移包位置与用途

本次交付包放在 `F:\天眼系统`。它使用相对路径配置，可以直接在该目录运行，也可以把整个目录复制到新服务器与当前服务器一致的安装路径；不要只复制其中的 `程序代码` 或数据库文件，也不要与旧目录残留文件合并覆盖。

迁移包用于执行当前投顾每日增量 DAG：天天投顾、广发基金、广发证券、且慢、数据加工、数据稽核、成功备份、最小发布集生成及 GitHub/EdgeOne 发布。南方基金当前为停用节点；私募处理不在每日 DAG，也不在本迁移包范围内。

## 2. 已包含内容

- `程序代码`：节点调度、采集、加工、稽核、报表和发布程序的受控运行快照。
- `数据库`：通过 SQLite Backup API 生成的一致性主库、监控库和更新状态库。
- `采集数据`：当前启用渠道的最近完整标准化基线，以及下一次增量必需的设备缓存、穿透缓存、协议缓存和且慢已验收历史基线。
- `本机配置/runtime.local.json`：与源机一致的相对路径、渠道、发布和备份配置。
- `结果文件/最小发布集`：`invest/main` 的浅克隆发布工作树，避免携带源机约 5 GB 的历史 Git 对象。
- `迁移基线`：迁移清单、数据库水位、校验和、最新成功摘要及稽核摘要。
- `00_每日数据更新并发布_唯一入口.bat`：唯一生产入口。

## 3. 未包含内容

- 历史日志、失败批次、调试截图、反编译文件、旧报表、旧数据库备份。
- 可由主库重建的正式页面和月报静态文件；最小发布仓库中不携带月报。
- 已经入库的全量历史原始响应和全部历史标准化批次。
- 源机 `运行环境/python`。Python 虚拟环境包含源机用户目录和绝对路径，必须在新服务器重新创建。
- 南方基金和私募账号配置、浏览器 Cookie/用户目录、密码明文。

## 4. 新服务器首次准备

1. 确认旧电脑的每日更新已经停止，且新旧电脑不会同时写库或发布。
2. 将整个目录复制到新服务器的 `F:\天眼系统`。
3. 保证系统盘和 F 盘均有足够空间；F 盘建议至少保留 45 GiB 可用空间，首次初始化会再创建一个主库成功备份。
4. 以下示例用 `F:\天眼系统` 作为工作区。如果新服务器实际安装路径不同，只替换 `$WorkspaceRoot` 的值。双击唯一入口前，先在 PowerShell 执行：

   ```powershell
   $WorkspaceRoot = "F:\天眼系统"
   powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File "$WorkspaceRoot\程序代码\节点脚本\_共享组件\生产程序\install_runtime_environment.ps1" -WorkspaceRoot $WorkspaceRoot
   ```

   该脚本会检查/安装 Python 3.12、Git、Node.js，并在 `F:\天眼系统\运行环境\python` 创建本机虚拟环境和安装依赖。服务器不能使用 `winget` 时，应先手工安装这三项再重跑。
5. 配置 GitHub 凭据。确认以下命令成功，不能只确认网页能打开：

   ```powershell
   git -C "$WorkspaceRoot\结果文件\最小发布集" remote -v
   git -C "$WorkspaceRoot\结果文件\最小发布集" push --dry-run origin main
   ```

6. 连接唯一实体手机，开启 USB 调试并确认 ADB 授权。生产链路只允许真机，不得安装或启用 MuMu。执行：

   ```powershell
   & "$WorkspaceRoot\程序代码\tools\platform-tools\adb.exe" devices -l
   ```

   `本机配置/runtime.local.json` 当前保留源机 `physicalDeviceId`。如果使用无线 ADB，换服务器后通常需要重新配对/连接并更新该字段；如果使用 USB，则填入真机序列号。
7. 在手机上检查天天基金、广发基金和广发证券 App 登录状态。App 登录状态保存在手机，不在迁移包内。
8. 且慢密钥为 Windows DPAPI `CurrentUser` 机器绑定密文。换电脑或换 Windows 用户后必须重新进行官方短信授权并在目标机生成 `本机配置/qieman_stargate_api_key.dpapi`；不能因为复制后文件存在就认为授权可用。操作边界见 `程序代码/official_apps/qieman/authenticated_probe/README.md`。

## 5. 首次验收与运行

安装依赖、配置 Git、接好真机并完成登录后，依次执行：

```powershell
Set-Location $WorkspaceRoot
& ".\00_每日数据更新并发布_唯一入口.bat" check
& ".\00_每日数据更新并发布_唯一入口.bat" initialize
& ".\00_每日数据更新并发布_唯一入口.bat"
```

- `check`：检查路径、Python/Node/Git、数据库、真机和网络。
- `initialize`：逐文件校验迁移基线、执行 SQLite `quick_check`，并创建一个成功基线备份。
- 无参数入口：执行完整每日更新、稽核、备份和发布。

首次完整运行结束后，应同时满足：

- 控制台退出码为 0，最终节点结果不是仅有进程成功。
- `运行状态/logs/daily_update` 中最新批次完成。
- 最终数据稽核无 `error`；`warn` 需单独解释，不能当成传输损坏。
- `数据库备份` 只保留一个经验证成功版本。
- `结果文件/最小发布集/version.json` 的 `buildId` 与线上版本一致。
- GitHub 与 EdgeOne 两个目标的发布结果均按当前 `runtime.local.json` 核对。

建议连续手工成功运行两次后，再接入 Windows 任务计划程序。任务计划只调用：

```text
F:\天眼系统\00_每日数据更新并发布_唯一入口.bat
```

不要传跳过稽核、跳过备份或跳过发布参数。

## 6. 常见问题

- `Python 环境不可用`：删除旧机复制来的 `运行环境/python`（本包默认不带）并重跑环境安装脚本。
- `device not found/offline`：重新确认手机 USB 授权；无线 ADB 需重新 `adb pair`/`adb connect` 并更新设备 ID。
- `DPAPI unprotect failed`：且慢密钥属于另一台机器或另一 Windows 用户，需在目标机重新授权。
- `git push` 失败：先配置 Git Credential Manager 和目标账号权限，再做 `push --dry-run`。
- 页面构建前目录为空：这是正常的最小化策略，正式页面由首次完整运行从主库重建。
- 迁移后不要让两台电脑同时运行；SQLite、采集断点、备份和发布仓库都只允许单写者。
