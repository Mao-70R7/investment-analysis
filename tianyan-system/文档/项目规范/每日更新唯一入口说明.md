# 每日更新唯一入口说明

## 日常操作

每天只运行项目根目录下的：

```text
00_每日数据更新并发布_唯一入口.bat
```

正常情况下直接双击，不需要填写参数，也不要分别执行其他采集或发布脚本。

## 默认执行流程

1. 仅预检 `本机配置/runtime.local.json` 中配置的实体手机，最多复检 3 次；不启动、不探测模拟器。
2. 正常批次的策略详情、当前持仓、调仓历史和官方曲线设备复核全部固定使用该真机；单策略内部两次尝试仍失败时，只把失败策略交给同一真机执行第二批次补采，不重跑成功策略。
3. 检查天天投顾和广发基金数据是否就绪；未就绪时每 30 分钟检查一次，最多 6 次。
4. 增量更新策略基础信息、业绩、当前仓位、调仓、新策略和仓位基金净值；公开净值接口失败项按降并发、延长超时方式再重试两轮。
5. 重建正式页面数据并执行完整数据稽核。
6. 仅在增量更新和数据稽核均成功后备份数据库，滚动保留最近两个成功版本。
7. 构建最小发布集并发布到 GitHub。

真机设备 ID 读取 `本机配置/runtime.local.json` 的 `physicalDeviceId`，并兼容显式环境变量 `ADVISOR_PHYSICAL_DEVICE_ID`。真机三次预检仍不可用时，设备分支不会启动，也不会使用模拟器代替；其他不依赖设备的独立渠道仍按节点调度规则继续。

任一核心步骤失败后，后续成功备份和发布不会继续执行。失败运行不会生成数据库备份，也不会清理已有的两个成功备份。

## 运行时查看

控制台会持续显示：

- 总步骤数和完成百分比。
- 已完成步骤和剩余步骤。
- 当前执行步骤及其耗时。
- 天天投顾和广发基金各采集子阶段的已完成策略数/总策略数、成功数、失败数和当前策略。
- 真机首轮失败数、同一真机第二批次补采目标数、补采成功数和最终失败数。
- 基金净值首轮失败数、每轮重试目标/成功/空返回/失败数，以及是否触发当前持仓发布门禁。
- 子阶段已耗时和按当前平均速度估算的剩余时间；主流程每 30 秒重复最近一条子任务进度。
- 最终成功或停止状态。

日志位置：

```text
logs\daily_update_console   完整控制台日志
logs\device_preflight      真机预检、选择结果和失败原因
logs\daily_update           每日主流程及分阶段日志
logs\incremental_update     增量采集明细和缺口汇总
```

运行结束后，优先查看 `logs\daily_update_console` 中日期和时间最新的 `.log` 文件。

## 中断后恢复

如果日志中给出了 `run_id`，修复登录、设备或网络问题后，可在项目目录的命令行执行：

```bat
00_每日数据更新并发布_唯一入口.bat -ResumeRunId 对应的run_id
```

恢复时会复用已经成功完成的阶段。增量采集子流程已经成功、仅外层状态中断的情况，也会根据成功摘要恢复，不会重复采集。

## 其他脚本的定位

根目录和 `scripts` 目录中的其他 `.bat`、`.ps1` 继续保留，用于专项补采、问题修复、单渠道验证和兼容旧调度。它们不属于每日标准入口，日常不要单独运行。

固定调用链如下：

```text
00_每日数据更新并发布_唯一入口.bat
  -> run_daily_update.ps1
  -> 节点脚本\_共享组件\生产程序\select_daily_update_device.py（仅真机）
  -> scripts\daily_update_orchestrator.py
```
