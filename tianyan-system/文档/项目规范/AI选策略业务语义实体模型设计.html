为什么重构

从“问题视图”改为“业务本体”

问题示例可以进入回归测试和别名字典，但不能成为架构主干。否则每出现一种表达，就要增加一条提示词或专用候选路径。

上一版：问题驱动

  • 维护生命周期日期、回撤风险、基准、持仓实体等固定检索视图。
  • 领域、概念和物理字段之间缺少事实类型与数据粒度。
  • 页面宽表容易被误当成完整业务模型。
  • 空值、时间、继承、证据和质量语义不够统一。
→

新版：业务本体驱动

  • 先识别业务对象和事实类型，再按元数据动态召回概念。
  • 显式区分观察、快照、头寸、事件、关系、政策、证据和投影。
  • 物理字段只在最后执行绑定阶段出现。
  • 字典强制包含粒度、时间轴、空值、来源、质量与操作符。

业务框架层次

六层模型：从业务对象到执行绑定

每一层解决一种问题。普通模型主要工作在“业务主题 + 标准概念”，不直接接触全量字段和底层表结构。

L1

业务对象层

策略、渠道、投顾机构、基金等稳定身份对象，解决“在问谁”。

L2

业务事实层

关系、观察、快照、头寸、事件、政策、分类、证据，解决“发生了什么、在哪个粒度”。

L3

业务主题层

治理、身份、生命周期、业绩、风险、持仓、调仓、信号、基准、费率和质量，解决“属于哪个业务框架”。

L4

标准概念层

稳定概念ID、业务定义、别名、适用范围和概念关系，解决“用户真正表达了哪个概念”。

L5

数据字典契约层

类型、单位、值域、空值、时间轴、来源、质量和操作符，解决“这个概念如何被精确表达”。

L6

执行绑定层

147个物理字段、13个虚拟字段或底层事实查询计划，解决“当前系统怎样准确执行”。

Σ

宽表是投影，不是本体

例如一个页面收益字段来自日度或区间观察，一个持仓权重来自最新快照的基金头寸聚合。v2 保留源粒度和时间语义，避免模型仅凭字段名称把不同事实混为一类。

数据字典规范

字典必须能约束模型，也能约束执行器

当前页面147字段已有114个说明，仍有33个缺说明。v2 不只补“中文描述”，而是建立20项机器可执行元数据契约。

一个合格字典条目必须回答

  1. 它属于哪个业务实体、哪类事实、什么粒度？
  2. 值是什么类型、单位和值域？空值意味着什么？
  3. 使用哪条时间轴、允许哪些操作符？
  4. 如何标准化，在哪些策略或事实范围内适用？
  5. 来源、继承、算法、证据和质量状态是什么？
  6. 最终绑定到宽表、虚拟字段还是底层事实查询？

通用渐进式结构

10个阶段，每次只解决一个问题

点击阶段可展开输入、输出和责任边界。黄色为普通模型，蓝色为编译器，绿色为数据库，其余由确定性程序或检索服务完成。

小上下文

首轮只看实体类型和事实类型，不看147字段。

候选动态生成

按实体、事实、粒度、类型和操作符检索Top-K。

确定性收口

日期、单位、枚举、绑定、逻辑和执行都由程序完成。

0请求封装deterministic · request

输入：原始查询、锚点时间、用户上下文。

输出：规范文本、requestId、anchorTime。只做字符和上下文封装。

1语义框架model · request

只发送：业务对象类型、事实类型和逻辑Schema。

只输出：子句、逻辑树、目标实体、事实类型、度量、时间、关系和值表面形式。

2概念检索retrieval · clause

按结构化元数据先过滤，再做别名、文本或向量召回。每子句建议最多5个概念候选。

3字典细化deterministic · clause

只展开候选概念及一跳关系，提供定义、粒度、类型、单位、值域、操作符、时间、空值、质量和执行绑定。

4受约束决议model · clause

模型只能从候选目录中选择概念、关系和操作符骨架；必须结构化说明其他候选为何被排除。

5值标准化deterministic · clause

程序计算日期、比例、单位、枚举和实体标准值；模型不做数学和日历运算。

6执行绑定compiler · clause

在物理字段、虚拟字段和底层事实查询之间选择粒度、时间和质量都一致的绑定。

7全局校验compiler · global

统一AND/OR/NOT、时间锚点、跨粒度连接、重复条件和冲突条件；必要时才提出澄清。

8查询执行database · global

使用参数化计划执行，记录每个条件前后的策略数、缺失数和命中证据。

9解释审计deterministic · global

从结构化轨迹生成解释，区分无匹配、数据缺失、不适用和低置信度，不让模型自由发挥。

子句并发

阶段2—6按原子子句独立处理，降低单次问题大小和模型负担。

→
全局汇合

等待全部子句后，统一逻辑、实体、时间、粒度和重复条件。

→
一次执行

生成一个可审计查询计划，避免各子句独立执行导致集合逻辑错误。

普通模型责任边界

模型做判断，程序做计算和约束

弱模型的正确用法不是给它更多规则，而是缩小每次选择空间、固定输出结构、取消可以程序化的任务。

普通模型负责

  • 切分原子子句和逻辑关系。
  • 识别目标业务对象、事实类型和语义角色。
  • 在Top-K候选概念中做受约束选择。
  • 输出置信度和被排除候选的结构化原因。

确定性系统负责

  • 概念召回、字典展开和候选裁剪。
  • 日期、比例、单位、枚举和实体标准化。
  • 字段/事实绑定、质量门禁和跨粒度查询编译。
  • 执行、数量核对、解释轨迹、缓存和版本管理。

质量与可解释性

语义正确不等于数据完整

每个概念和绑定都必须带质量状态。低覆盖字段可能是适用范围小，也可能是采集缺口；二者不能由模型自行猜测。

verified

定义、来源、粒度和值可核验。

usable_with_limit

可执行，但必须披露限制。

sparse

只在明确适用范围内启用。

missing

不生成普通筛选条件。

conflicting

按权威顺序消解或阻断。

not_applicable

不进入有效分母。

derived_unverified

只作候选或证据。

实施路径

先补元数据，再替换模型调用

不建议直接把 v2 JSON 塞进现有提示词。应先建立目录加载、检索、字典细化和查询编译能力，再灰度接入模型。

确认模型

确认21类实体、14类事实、时间轴、空值语义和六层边界。

补齐字典

补33个缺说明字段，并扩展为20项机器可执行元数据。

构建索引

生成概念、关系、值域、质量和执行绑定的版本化检索索引。

实现协议

依次实现语义框架、候选检索、字典细化和受约束决议。

实现编译器

确定性标准化、质量门禁、跨粒度连接和全局逻辑计划。

建立回归集

按业务主题、事实类型、粒度、否定、时间和组合逻辑覆盖测试。

影子运行

新旧解析并行，比较概念、条件、结果集合、耗时和澄清率。

灰度切换

按置信度和主题逐步放量，保留旧解析器回退与完整审计轨迹。

建议本次确认的五项决策

1

宽表定位
